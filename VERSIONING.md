# Версионирование Android-приложения

Android-приложение версионируется независимо от Python CLI. Единственный источник версии — `version.properties` в корне Android-проекта. Gradle читает `VERSION_NAME` и `VERSION_CODE` и применяет одну и ту же пару ко всем трём распространяемым GitHub APK: `arm64-v8a`, `armeabi-v7a` и `universal-arm`. Все эти APK одной публикации являются вариантами одной версии и должны иметь совпадающие идентификаторы версии.

## Правила версий и сборок

- `VERSION_NAME` — SemVer `MAJOR.MINOR.PATCH`:
  - PATCH — совместимые исправления и рефакторинг;
  - MINOR — новая совместимая функциональность;
  - MAJOR — несовместимые изменения.
- `VERSION_CODE` — целое число от 1 до 2100000000. Увеличивать при каждом значимом билде, публикуемом или предназначенном для распространения; значение должно расти монотонно и не сбрасываться при смене MAJOR.
- Обновлять пару `VERSION_NAME`/`VERSION_CODE` в `version.properties` для каждого значимого билда, чтобы различать APK и не предлагать Android уже установленную либо устаревшую сборку как более новую.
- Каждый релизный набор из трёх APK маркировать prerelease Git-тегом формата `vMAJOR.MINOR.PATCH-alpha`, соответствующим `VERSION_NAME`. Например, для версии `1.2.3-alpha` тег имеет вид `v1.2.3-alpha`. Alpha-тег и GitHub release создавать только при подготовке фактической публикации.
- `VERSION_CODE` должен быть выше, чем у всех ранее распространявшихся APK.

Проект находится в alpha/beta-разработке. Планируемая alpha-публикация на GitHub ещё не создана; не считать тег или релиз существующим до фактического выпуска.

## Проверка перед публикацией

```bash
./gradlew :app:testDebugUnitTest :app:assembleDebug :app:assembleRelease :app:lintDebug
python3 tools/check_lint.py
```

Перед публикацией проверить, что тесты проходят, debug-сборка и lint успешны, lint gate пройден, все три APK созданы с одинаковыми `VERSION_NAME` и `VERSION_CODE`, а их ABI соответствуют названиям вариантов. Проверить, что версия и `VERSION_CODE` согласованы с планируемым prerelease-тегом и превышают опубликованные ранее значения. Release APK подписывать стабильным release-ключом; подписи debug и release несовместимы для обновления приложения поверх установленной копии. Ключи подписи, VOT и прочие секреты не хранить в Git или в отслеживаемых конфигурационных файлах.
