# Версионирование Android-приложения

Android-приложение версионируется независимо от Python CLI.
Единственный источник версии — `version.properties` в корне Android-проекта.
Gradle проверяет значения и использует их как `versionName` и `versionCode`.
Начальная версия baseline: `0.1.0`, код `1`.

## Правила выпуска

- `VERSION_NAME` — SemVer `MAJOR.MINOR.PATCH`:
  - PATCH: совместимые исправления и рефакторинг;
  - MINOR: новая совместимая функциональность;
  - MAJOR: несовместимые изменения.
- `VERSION_CODE` — целое число от 1 до 2100000000; увеличивать для каждого
  выпуска независимо от изменения компонентов SemVer. Не сбрасывать при смене MAJOR.
- Промежуточные коммиты одного невыпущенного этапа не требуют отдельной версии.
- Перед коммитом завершённого изменения обновлять версию, если этого требует
  характер изменения. Первый коммит фиксирует исходную версию без повышения.
- Выпуски отмечать аннотированным тегом `vMAJOR.MINOR.PATCH` только по явному
  запросу пользователя, после успешных тестов, сборки и lint.
- Коммиты оформлять на русском языке в формате Conventional Commits:
  `<тип>: <описание в повелительном наклонении>`.

## Проверка перед выпуском

```bash
./gradlew testDebugUnitTest assembleDebug lintDebug
```

Проверить, что код версии выше всех ранее выпущенных APK, а версия в
`version.properties` соответствует планируемому тегу. Секреты и локальные
параметры подписи в Git не включать.
